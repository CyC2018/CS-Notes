## 一、说明

适合会一门编程语言（Python 或 Java）、准备大模型应用开发面试的读者，每天约 1～1.5 小时。动手部分需要一个兼容 OpenAI 接口的模型服务（例如 DeepSeek）或本地的 Qwen2.5 小模型；学过 Java 后端路线的读者可以跳过算法题。

每天先读完阅读范围，再不看笔记回答自测题，答完打开链接核对。选读可以跳过。

## 二、开始之前

本路线不讲语法。动手部分大多用 Python，开始前先确认能独立写出下面 5 个程序：

1. 调用 https://api.github.com/repos/CyC2018/CS-Notes ，解析返回的 JSON，打印 stargazers_count；
2. 读取一个 JSON Lines 文件（每行一个订单，含 user_id 和 amount），统计每个用户的订单数和总金额，写入 JSON 文件；
3. 把一段长文本切成不超过 200 字的片段，只在句号处切分；
4. 用列表保存对话历史，只保留最近 10 条消息；
5. 请求超时时重试，最多 3 次，每次等待的时间翻倍。

写不出来的，先补对应的语法：HTTP 请求与 JSON、文件读写、字符串、列表、异常与循环。用 Java 写同样的程序也可以。

## 四、大模型基础

### 第 1 天：Token 与 Transformer

Token 是模型处理文本的单位，也是计费和上下文长度的单位。Transformer 一节先看整体结构，再看参数分布在哪里；混合专家可以略读。

阅读：《大模型应用》从[Token 与分词](大模型应用.md#token-与分词)读到[Transformer 结构](大模型应用.md#transformer-结构)。

自测：

1. Transformer 的结构是怎样的？（见[整体结构](大模型应用.md#1-整体结构)）
2. 大模型的参数主要分布在哪里？（见[参数都在哪里](大模型应用.md#2-参数都在哪里)）
3. 什么是 Token？同样的内容，中文和英文的 Token 数一样吗？（见[Token 与分词](大模型应用.md#token-与分词)）

动手：下载 Qwen2.5-7B-Instruct 的 config.json，按[参数都在哪里](大模型应用.md#2-参数都在哪里)一节的方法算出一层中注意力和前馈网络的参数量，再与[附录 A16](大模型应用.md#a16-qwen25-7b-与-qwen3-30b-a3b-的参数量)对照。

算法（哈希表，简单）：[1. 两数之和](https://leetcode.cn/problems/two-sum/)，题解见[数组中两个数的和为给定值](Leetcode%20题解%20-%20哈希表.md#1-数组中两个数的和为给定值)。

### 第 2 天：注意力机制

注意力是 Transformer 的核心，对着“饿”的例子把 Q、K、V 的计算走一遍。FlashAttention 一节说明了长上下文时计算的瓶颈在哪里。

阅读：《大模型应用》的[注意力机制](大模型应用.md#注意力机制)。选读：[进阶：注意力机制](大模型应用%20-%20进阶.md#注意力机制)。

自测：

1. 注意力的计算公式是什么？为什么要除以 √d？（见[注意力机制](大模型应用.md#注意力机制)）
2. 多头注意力有什么作用？（见[多头注意力](大模型应用.md#1-多头注意力)）
3. FlashAttention 解决了什么问题？（见[计算量与 FlashAttention](大模型应用.md#2-计算量与-flashattention)）

动手：用 NumPy 实现单头注意力 softmax(QK<sup>T</sup> / √d) V，输入 3 个 Token、维度为 4 的随机矩阵，打印注意力权重并检查每一行的和是否为 1。

算法（双指针，中等）：[15. 三数之和](https://leetcode.cn/problems/3sum/)，题解见[三数之和](Leetcode%20题解%20-%20双指针.md#8-三数之和)。

### 第 3 天：生成、KV Cache 与采样

模型每次只生成一个 Token。KV Cache 避免重复计算前面 Token 的 K 和 V，也是推理时显存的主要来源。采样参数决定每一步怎样从概率分布中选出 Token。

阅读：《大模型应用》从[自回归生成与 KV Cache](大模型应用.md#自回归生成与-kv-cache)读到[采样参数](大模型应用.md#采样参数)。选读：[进阶：自回归生成与 KV Cache](大模型应用%20-%20进阶.md#自回归生成与-kv-cache)。

自测：

1. KV Cache 是什么？为什么能加快生成？（见[自回归生成与 KV Cache](大模型应用.md#自回归生成与-kv-cache)）
2. MHA、MQA 和 GQA 有什么区别？（见[自回归生成与 KV Cache](大模型应用.md#自回归生成与-kv-cache)）
3. temperature 和 top-p 分别控制什么？（见[采样参数](大模型应用.md#采样参数)）

动手：按[显存：权重与 KV Cache](大模型应用.md#3-显存权重与-kv-cache)一节的方法，算出 Qwen2.5-7B 在 32K 上下文、同时处理 8 个请求时 KV Cache 占用的显存。

算法（滑动窗口，中等）：[3. 无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)，题解见[剑指 Offer 48](48.%20最长不含重复字符的子字符串.md)。

### 第 4 天：训练过程

按预训练、监督微调、偏好对齐三个阶段读。PPO、DPO 和 GRPO 的区别是常见的追问，比较时看每种方法需要哪些模型。

阅读：《大模型应用》的[训练过程](大模型应用.md#训练过程)。选读：[进阶：训练过程](大模型应用%20-%20进阶.md#训练过程)。

自测：

1. 大模型的训练分为哪几个阶段？（见[三个阶段](大模型应用.md#1-三个阶段)）
2. PPO、DPO 和 GRPO 有什么区别？（见[DPO](大模型应用.md#3-dpo)、[GRPO 与三者的选择](大模型应用.md#4-grpo-与三者的选择)）
3. RLHF 中的奖励模型是怎样训练的？（见[RLHF 与 PPO](大模型应用.md#2-rlhf-与-ppo)）

动手：用 Python 按[DPO](大模型应用.md#3-dpo)一节的公式，对几组给定的 chosen 和 rejected 对数概率计算 DPO 损失，观察 β 取 0.1 和 0.5 时损失的变化。

算法（链表，简单）：[206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)，题解见[链表反转](Leetcode%20题解%20-%20链表.md#2-链表反转)。

### 第 5 天：微调与量化

先判断什么时候该微调、什么时候用 RAG 或提示词就够了。LoRA 是最常用的微调方法；量化一节中 GPTQ 与 AWQ 可以略读。

### 第 6 天：幻觉与推理模型

综合题：一个客服机器人的每次请求都要带上系统提示词、工具定义、用户资料和最近的对话：怎样安排它们的顺序？Token 超出预算时先裁掉什么？（见[放什么、按什么顺序](大模型应用.md#1-放什么按什么顺序)、[Token 预算](大模型应用.md#2-token-预算)、[让前缀缓存命中](大模型应用.md#3-让前缀缓存命中)）
